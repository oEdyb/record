# Recorder interaction audit

The recorder needs one persistent object and one interaction model. Changing the spring alone cannot repair disappearing identity, inconsistent expansion commands, or disagreement between painted and native hit regions.

Scope: floating and docked recorder, Setup, Source, transport, Replay, pointer, drag, keyboard and accessibility. Preserve clip-native capture, writer-confirmed state, source recovery and review. No archived editor additions. Date: October 26, 2026, Europe/Stockholm.

## Ranked findings

The first five findings describe the inspected baseline. The implementation below addresses their causes; acceptance checks remain deliberately broader than the evidence collected so far.

1. **P1 — identity is replaced instead of carried.** `LaunchWindow.module.css` selectors for the top-docked `.hudPillRow` fade controls over 100–180 ms while the shell transforms for 600 ms; `.hudDockTab[data-covered]` fades independently. `LaunchWindow.tsx` renders separate collapsed and expanded timers. A connected outline alone does not make these contents one object. Keep one central mark/timer mounted and reveal controls through the growing bounds.
2. **P1 — opening changes meaning across inputs.** The tab's `HudDragHandle.onTap` calls `undockHud`; hover calls `setDockPeek`. “Expand” therefore clears docking for click/keyboard but preserves it for hover. Keyboard focus does not hold provisional expansion. Separate expand/collapse from docking, and keep focus and child panels inside the expanded interaction region.
3. **P1 — native and painted footprints disagree.** `measureHudSize` selects `dockTabRef` whenever docked, including hover expansion; `hudBoundsAtEdge` clamps only that reported footprint. A tab near a top corner can reveal a larger pill beyond the display. Reserve the expanded footprint when positioning the dock, while preserving its stable anchor during the morph.
4. **P1 — pointer intent has two competing owners.** `scheduleDockPeek` uses DOM enter/leave timers while `onHudPointerCheck` only updates click-through. The native watch originally stops when click-through is enabled. Inactive-window events and changing hit geometry can consequently disagree with expansion state. Reconcile native cursor samples and DOM input through one controller. Do not derive intent from arbitrary descendant animations.
5. **P2 — current evidence cannot establish native usability.** `tests/e2e/hud-hover.spec.ts` mocks dock IPC and asserts the literal 0.6 s transition. Unit tests synthesize event order. Neither proves display clamping, first-click delivery or repeated hover on an inactive native panel. `HANDOFF.md` explicitly records an unsuccessful repeated-hover collector run. Replace timing-value assertions with observable continuity and interaction checks; retain real Mac validation.

## Additional gaps outside the morph

- **P2 — Setup and Source expose incomplete composite semantics.** `SourceSelector.tsx` declares tabs but has no arrow-key navigation, selected-tab tab stop, or tab/panel ID linkage. `HudDeviceSettings.tsx` declares source and quality buttons as radios without radio-group arrow navigation; quality uses a fieldset rather than a radiogroup. Either implement the advertised patterns or use ordinary action buttons where choosing opens a picker rather than immediately changing selection. Implemented with behavioral tests; see verification limits below.
- **P2 — panel focus has no complete round trip.** Setup/Source have no explicit keyboard entry or trigger restoration. Replay focuses its Play button on open (`HudClipPeek.tsx`) but its close path does not restore the invoking control. Closing can leave focus on a hidden/unmounted element. Track the invoker, enter a useful panel control for keyboard opening, and restore focus on dismissal. This is separate from holding the dock open while focus remains inside. Setup/Source entry and restoration are implemented and browser-verified; Replay invoker restoration remains outstanding.
- **P2 — Replay failure has no actionable presentation.** `HudClipPeek.tsx` catches a non-interruption play rejection by setting `playing=false`; neither media element has `onError`. A missing or undecodable clip can look merely paused. Show a bounded error with retry/close while retaining Continue and Stop; never modify the take to recover playback. Failure-path verification pending.

The existing transport guards are useful foundations: `canPeek` requires a completed pause and a kept clip; `controlsLocked` covers startup, saving, finalization and active capture; the remove path provides Undo feedback. Preserve these. This inspection does not establish native writer correctness.

## Interaction design

- Keep recording state, dock location and expansion independent. Idle exposes source/audio/mic/camera/Setup/Record. Capture and pause share Pause/Continue, timer, Stop, Remove, Replay and Setup; transport positions do not change on Pause.
- Hover opens provisionally after a short intent threshold. Click, Enter or Space holds the same attached recorder open. Escape closes a child panel first, then collapses the recorder and focuses its trigger. Only drag/pull changes docking. Pointer, focus, drag and open child panels all hold expansion.
- Retain one central Klippt mark when idle and one actual timer/state mark during a take. Reveal natural-size controls on both sides as the shell grows. Use one progress for shell and matching mask; remove whole-row opacity swaps. Retarget from the current shape during reversal. Reduced motion keeps the same interaction contract without shape travel.
- Keep the native backing window stationary during expansion, sized for existing panels. Clamp the full expanded recorder to its display before settling the dock. Transparent margins pass clicks through; visible enabled controls receive the first intentional click. Native probes must not steal application focus.
- Setup changes while paused apply only to the next clip. Record remains unavailable until source/preferences are ready. Startup never advances the timer before writer confirmation; Pause finalization and Stop saving retain clear busy feedback. A graceful morph must never delay transport execution.

## Acceptance checks

1. **Continuous object:** inspect frame captures of both directions and reversal at 25%, 50% and 75%. One connected outline; no blank, duplicated, scaled or jumping mark/timer; no control painted outside the moving boundary. Verify idle, capture, paused, starting and saving, including reduced motion.
2. **Reliable pointer and drag:** 20 native open/close cycles from tab center and bottom edge while another app is active. Hold still two seconds after each opening. Zero extra pointer wiggles, false collapses or missed first clicks. Tap does not drag; drag does not toggle; release/cancel stops movement. Repeat across display boundaries and after sleep/wake.
3. **Input and focus:** click/Enter/Space expand without clearing saved dock choice. Move focus through every enabled control with the pointer outside: no collapse. Keyboard-open and dismiss Setup, Source and Replay, including selects rendered in portals; focus returns to the invoker. Radios/tabs follow their declared keyboard pattern. Touch/pen activation must not depend on hover.
4. **Geometry:** test both top corners, side docks, shortened work areas and two displays, in idle/capture/paused states and long timer/source labels. All controls remain within the work area; expansion causes zero native window moves/resizes. Clicking transparent backing reaches the app underneath.
5. **Actual recording:** after expansion and mid-close reversal, Pause/Continue/Stop execute on first activation and agree with writer events and durable clips. Test fast Pause→Stop, repeated Pause/Continue, removal to zero and Undo; paused device/source changes affect only the next clip. Replay missing/corrupt-media failure offers recovery without altering originals. Capture content protection remains enabled for real recording checks.

## Primary sources and tool choice

Sources checked October 26, 2026:

- [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md): semantic controls, visible/grouped focus, reduced motion and interruptible motion. Applied proportionally to this recorder; its generic advice does not override clip-removal product decisions.
- [Electron BaseWindow mouse forwarding contract](https://github.com/electron/electron/blob/main/docs/api/base-window.md#winsetignoremouseeventsignore-options): forwarding concerns mouse movement while ignoring input; it is disabled when ignoring is false. Forwarding is not a guarantee of every pointer/focus transition. The repository pins Electron 44.9.1; current documentation informs the design, and exact runtime behavior remains a native acceptance gate.
- [Apple Designing Fluid Interfaces](https://developer.apple.com/videos/play/wwdc2018/803/): continuous feedback, preserved gesture attachment and purposeful motion. This is interaction guidance, not an Electron API contract or a universal spring setting.
- [Motion layout and shared elements](https://motion.dev/docs/react-layout-animations): `layout` and `layoutId` animate geometry; coexisting matched elements crossfade automatically, and scaled children can distort. The documented facilities do not supply recorder state, native click-through, focus retention or display placement.
- [MDN pointerenter](https://developer.mozilla.org/en-US/docs/Web/API/Element/pointerenter_event): entry follows hit-test boundaries and can occur on non-hover pointerdown. Input policy must distinguish hover capability from deliberate activation.
- [WAI radio-group pattern](https://www.w3.org/WAI/ARIA/apg/patterns/radio/): declared radios require matching focus and arrow-key behavior.

Current motion libraries and the installed design skills help evaluate and implement motion; they cannot decide what “expand” means or repair native/DOM disagreement by themselves. Installing Motion or changing an easing would leave the main defects intact, and automatic shared-element crossfade would reproduce part of the complaint. Start with the persistent object, explicit input contract and actual native evidence. No new package is required for that design.
